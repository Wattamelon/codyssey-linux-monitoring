# SSH 포트 변경 후 LISTEN 되지 않던 문제 해결

## 문제 상황

`/etc/ssh/sshd_config` 파일에서 아래 설정을 수정하였다.

```text
Port 20022
PermitRootLogin no
```

이후 SSH 서버를 실행하고 아래 명령어로 포트 상태를 확인하였다.

```bash
ss -tulnp | grep 20022
```

하지만 아무 결과도 출력되지 않았다.

즉, `sshd`가 20022 포트에서 LISTEN 상태로 동작하지 않는 문제가 발생하였다.

---

## 원인 분석

`sshd_config`를 수정한 후 기존 `sshd` 프로세스가 이전 설정 상태로 계속 실행 중이었다.

즉:

* 설정 파일은 수정되었지만
* 기존 SSH 서버 프로세스는 재시작되지 않아
* 새로운 포트 설정(20022)이 반영되지 않은 상태였다.

---

## 해결 방법

기존 SSH 서버 프로세스를 종료한 후 다시 실행하였다.

```bash
pkill sshd
/usr/sbin/sshd
```

이후 다시 포트 상태를 확인하였다.

```bash
ss -tulnp | grep -E '22|20022'
```

---

## 결과

아래와 같이 `20022` 포트가 LISTEN 상태로 출력되는 것을 확인하였다.

```text
tcp   LISTEN 0      128          0.0.0.0:20022      0.0.0.0:*    users:(("sshd",pid=4730,fd=3))
tcp   LISTEN 0      128             [::]:20022         [::]:*    users:(("sshd",pid=4730,fd=4))
```

이를 통해:

* SSH 서버(sshd)가 정상 실행되었고
* 20022 포트에서 원격 접속 대기 상태임을 확인하였다.

---

## 학습한 내용

* `sshd_config`를 수정해도 기존 실행 중인 `sshd` 프로세스에는 자동 반영되지 않는다.
* 설정 변경 후에는 SSH 서버 재시작이 필요하다.
* `ss -tulnp` 명령어로 현재 LISTEN 중인 포트와 프로세스를 확인할 수 있다.
* Docker 컨테이너 내부에서도 일반 리눅스 서버와 동일한 방식으로 SSH 서버를 운영할 수 있다.
